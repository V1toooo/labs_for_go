# labs_for_go
Labs for GO extra course at SPbU

### #1 Окружение и первый Go-проект

1. Создать свой репозиторий, добавить в коллабораторы преподавателя (github.com/vacmannnn) и других кураторов. 
2. Создать Pull Request в ветку main в котором *минимум* должны быть:
    - go.mod
    - файл main.go
    - .gitignore
    
    ❗ **Название** PRa **обязано** включать в себя номер ДЗ. (напр. task 1/”Крутое название [1]”/Homework1/…)
    
3. В файле main.go должно быть решение задачи https://leetcode.com/problems/two-sum/description/: 
    - функция `twoSum(nums []int, target int) []int` с кодом решения
    - функция `main` , в которой вызывается twoSum с любыми аргументами
4. В описании Pull Request написать результат выполнения команд `go version` и `go env GOPATH` , например:
    
    ```shell
    ~/code/courses                                                         
    ❯ go version                                          
    go version go1.26.4 darwin/arm64
    
    ~/code/courses                                                                                                                                                                      
    ❯ go env GOPATH
    /Users/aleksandrlekomcev/go
    ```
    
### Критерии оценивания

6 баллов — Репозиторий создан, PR оформлен по всем правилам (название содержит номер ДЗ, добавлены go.mod, main.go, .gitignore). Функция twoSum работает для всех краевых случаев, код отформатирован gofmt, в описании PR указаны выводы команд. Коммиты информативные.

5 баллов — Все требования выполнены, но есть мелкие недочёты: например, в описании PR нет вывода go env GOPATH, или функция twoSum не обрабатывает случай с отрицательными числами, но основная логика верна.

4 балла — Репозиторий создан, PR есть, но отсутствует один из файлов (например, .gitignore) или функция twoSum работает только для частного случая (например, только для положительных чисел). Либо код не отформатирован, но компилируется.

3 балла — Репозиторий создан, но PR не соответствует требованиям (нет номера ДЗ в названии, нет описания). Функция twoSum содержит логические ошибки (не возвращает индексы или возвращает неверный результат). Либо отсутствует main или go.mod.

0–2 балла — Работа не сдана, скопирована, или репозиторий не содержит решения задачи twoSum. Либо PR не создан, либо код не компилируется. Структура ответа не соблюдена.

Отметка за задание снижается при более поздней сдаче задания (1 балл за каждые 2 недели опоздания).

### #2 CLI-загрузчик фильмов со стенда

Создать CLI-приложение, которое скачивает описания фильмов с homeworksite.site и выводит их в терминал в формате:

```
id — title — year — director
```

Описания фильмов скачиваются в промежутке [from; to], всего `to-from+1` фильм. Загрузка должна выполняться параллельно с помощью worker pool.

Флаги приложения:

- `--from=N` — id первого фильма, обязательный флаг.
- `--to=M` — id последнего фильма, обязательный флаг.
- `--workers=X` — количество воркеров в worker pool, опциональный флаг, по умолчанию 10.
- `--timeout=T` — таймаут одного HTTP-запроса, опциональный флаг, по умолчанию 5 секунд.

Отсутствие обязательных флагов, `from > to`, `workers <= 0` или некорректные значения флагов должны приводить к понятной ошибке и ненулевому коду завершения.

API homeworksite.site:

- `GET homeworksite.site/1/info.0.json` — возвращает JSON-описание фильма с `id=1`.
- `GET homeworksite.site/{id}/info.0.json` — возвращает JSON-описание фильма с указанным `id`.

Требования к обработке ошибок:

- если отдельный фильм не загрузился из-за `404`, `429`, `500`, битого JSON, таймаута или обрыва соединения, программа не должна падать целиком;
- по таким фильмам нужно вывести короткое сообщение об ошибке и продолжить обработку остальных id;
- при `Ctrl-C` программа должна отменить оставшиеся запросы через `context` и завершиться корректно.

Дополнительно: сравнить время запуска при `--workers=1` и `--workers=10` на одном и том же диапазоне фильмов и кратко написать вывод в описании PR.

### Критерии оценивания

6 баллов — Все флаги реализованы (--from, --to, --workers, --timeout), валидация аргументов корректна с понятными ошибками и ненулевым кодом выхода. Worker pool работает, загрузка параллельна, ошибки отдельных фильмов не роняют программу, Ctrl+C корректно отменяет контекст. В PR приложены результаты сравнения производительности.

5 баллов — Всё работает, но есть один недочёт: например, не обрабатывается timeout для отдельных запросов, или при ошибке не выводится понятное сообщение.

4 балла — Основная функциональность работает, но отсутствует валидация флагов (например, при from > to программа падает), или worker pool не используется (загрузка последовательная), или при Ctrl+C программа не завершается полностью.

3 балла — Программа запускается и что-то скачивает, но игнорирует ошибки (при 404 или 500 падает), или флаги обрабатываются некорректно (не работают значения по умолчанию). Нет контекста и таймаутов.

0–2 балла — Код не компилируется, или не скачивает ни одного фильма, или архитектура фундаментально неверна (например, синхронные запросы в цикле без обработки ошибок). Нет структуры, не соблюдены требования по оформлению PR.

Отметка за задание снижается при более поздней сдаче задания (1 балл за каждые 2 недели опоздания).

Дедлайн: 2 недели
